# PC Remote для Home Assistant

Кастомная интеграция Home Assistant для управления компьютерами с установленным
PC Remote.NET. Репозиторий публичный и содержит только исходный код интеграции:
`custom_components/pc_remote`.

Интеграция не является отдельным сервером и не открывает новые порты. Команды
передаются по существующему защищённому протоколу PC Remote. Для включения
компьютера используется встроенная в Home Assistant интеграция `wake_on_lan`.

## Что нужно заранее

- работающий Home Assistant;
- HACS (для установки из этого репозитория) или доступ к каталогу конфигурации;
- PC Remote.NET, установленный на Windows-компьютере ([страница релизов](https://github.com/RoXy228/PC-Remote-NET/releases));
- браузер, открытый на том же Windows-компьютере, который требуется связать.

Для автоматической привязки нужна сборка PC Remote.NET с поддержкой ссылки
`pcremote://` и Home Assistant pairing bridge. В старых релизах, где этого
обработчика ещё нет, ссылка не откроется и привязка невозможна. После установки
совместимой сборки запустите PC Remote.NET хотя бы один раз, чтобы Windows
зарегистрировала URI. Если в описании релиза явно не указана поддержка
Home Assistant pairing, используйте сборку, которую предоставляет автор
интеграции.

## Установка через HACS (рекомендуется)

1. В Home Assistant откройте **HACS → Интеграции**.
2. Откройте меню **⋮ → Пользовательские репозитории**.
3. Добавьте URL репозитория:

   `https://github.com/RoXy228/PC-Remote-NET-Plugin-Home-Assistant`

4. В качестве типа выберите **Integration** и нажмите **Добавить**.
5. Найдите **PC Remote**, нажмите **Скачать** и подтвердите установку.
6. Перезапустите Home Assistant.
7. Откройте **Настройки → Устройства и службы → Добавить интеграцию** и
   выберите **PC Remote**.

Пункт 7 только загружает интеграцию в Home Assistant. Он не выполняет привязку
к компьютеру. Для привязки используйте отдельную панель **PC Remote** в левой
боковой панели Home Assistant.

На странице **Настройки → Устройства и службы** должна быть одна запись PC
Remote. Если после нескольких попыток появились дубликаты, откройте меню **⋮**
у лишней записи и удалите её; профили компьютеров хранятся в самой интеграции.

## Ручная установка

Скопируйте каталог `custom_components/pc_remote` из этого репозитория в каталог
конфигурации Home Assistant:

~~~text
<config>/custom_components/pc_remote/
~~~

Например, итоговый путь должен выглядеть так:
`/config/custom_components/pc_remote/manifest.json`.
После копирования перезапустите Home Assistant и добавьте интеграцию через
**Настройки → Устройства и службы → Добавить интеграцию**.

## Привязка Windows-компьютера

Привязку нужно начинать в браузере, запущенном именно на нужном Windows-ПК.
Телефон, планшет или другой компьютер для этого шага не подходят.

1. На Windows-ПК откройте адрес Home Assistant и войдите пользователем с правами
   администратора.
2. В левой боковой панели откройте **PC Remote**.
3. Нажмите **Связать с этим ПК**.
4. В течение короткого времени подтвердите открытие ссылки `pcremote://pair`.
   Если Windows спросит, чем открыть ссылку, выберите PC Remote.NET. Если
   браузер не показал это окно, нажмите появившуюся в панели кнопку
   **«Открыть PC Remote»**.
5. В окне PC Remote.NET подтвердите сообщение о разрешении Home Assistant
   управлять компьютером.
6. Дождитесь сообщения об успешной привязке и обновите панель Home Assistant.

Ссылка одноразовая и быстро истекает. Если окно подтверждения не появилось или
ссылка устарела, нажмите **Связать с этим ПК** ещё раз и используйте только новую
ссылку. Для каждого дополнительного компьютера повторите процедуру в браузере
на этом компьютере; после привязки профиль можно переименовать (например,
«Основной компьютер» или «Ноутбук»).

Для повторной привязки уже добавленного компьютера используйте кнопку
**Привязать заново** в его карточке. Имя, внешний адрес и параметры
Wake-on-LAN сохраняются, а ключи связи заменяются.

При привязке автоматически передаются локальный адрес, MAC-адрес, TLS-
отпечаток и параметры Wake-on-LAN. Ключи создаются отдельно для Home Assistant
и сохраняются только локально в его хранилище.

> Для привязки предпочтителен HTTPS. При использовании обычного HTTP данные
> привязки передаются внутри локальной сети без шифрования, поэтому выполняйте
> её только в доверенной домашней сети, а не через публичный Wi-Fi.

## Управление

Панель **PC Remote** предназначена для выбора профиля, переименования
компьютера, назначения основного профиля и запуска доступных действий.
Поддерживаемые команды PC Remote:

~~~text
STATUS
SHUTDOWN
REBOOT
SHUTDOWN:15   REBOOT:15
SHUTDOWN:30   REBOOT:30
SHUTDOWN:60   REBOOT:60
SHUTDOWN:90   REBOOT:90
SHUTDOWN:120  REBOOT:120
CANCEL
LOCK
SCREEN_OFF
~~~

Включение выполняется действием Wake-on-LAN Home Assistant. Для него компьютер
должен поддерживать Wake-on-LAN, а профиль — содержать правильный MAC-адрес и
широковещательный адрес.

Интеграция также регистрирует действия `pc_remote.execute`, `pc_remote.wake` и
`pc_remote.cancel_timer`. Их можно вызывать из автоматизаций Home Assistant;
опасные действия (выключение и перезагрузка) следует защищать подтверждением
в используемом сценарии Алисы.

## Алиса и Yandex.Station Intents

Список фраз формируется в панели PC Remote кнопкой **Фразы для Алисы**. Скопируйте
полученный фрагмент в уже установленный сценарий `Yandex.Station Intents` и
свяжите каждую фразу с соответствующим действием `pc_remote.execute` или
`pc_remote.wake`. Сценарии подтверждения «да/нет/отмена» остаются в Home
Assistant. Для нескольких ПК используйте их имена из панели.

## Экспорт и безопасность

Обычный экспорт профилей не содержит ключей. Экспорт с секретами предназначен
только для локального резервного копирования и требует отдельного осознанного
подтверждения. Никогда не помещайте такой файл в Git, не отправляйте его в
публичные issue и не прикладывайте к логам.

Обычный экспорт можно импортировать как настройки: у уже существующих профилей
ключи сохранятся, а новые профили потребуется привязать заново. Для переноса
готовых к управлению профилей нужен полный экспорт с ключами.

В публичном репозитории нет паролей, токенов, приватных ключей, pairing-секретов
или пользовательских профилей. Секреты появляются только после привязки и
хранятся в локальном `.storage` Home Assistant.

## Обновление

Через HACS: **HACS → Интеграции → PC Remote → Обновить**, затем перезапустите
Home Assistant.

Если используется локальный клон, обновите его так:

~~~powershell
cd <путь-к-репозиторию>
git pull --ff-only origin main
git status
~~~

После ручного копирования обновлённого каталога в `<config>/custom_components/`
перезапустите Home Assistant.

## Публикация изменений (для разработчика)

~~~powershell
cd <путь-к-репозиторию>
git status
git add custom_components hacs.json README.md .gitignore
git commit -m "Update PC Remote Home Assistant integration"
git push origin main
~~~

Перед `git add` проверьте `git status` и убедитесь, что в коммит не попали
экспорты, `.storage`, логи, ключи или файлы из другой рабочей копии.

## Если привязка не работает

- **Видны две записи PC Remote.** Это две записи конфигурации, а не два ПК.
  Удалите лишнюю запись через меню **⋮**, оставьте одну и перезапустите HA.
- **Нет панели PC Remote в боковом меню.** Убедитесь, что интеграция установлена,
  Home Assistant перезапущен, а текущий пользователь — администратор. Обновите
  страницу с очисткой кэша браузера.
- **Кнопка сообщает, что нужен Windows-ПК.** Откройте HA в браузере на том ПК,
  где запущен PC Remote.NET. Это ограничение намеренное.
- **`pcremote://` не открывается.** Установите актуальный PC Remote.NET,
  запустите его один раз и повторите pairing. Проверьте, что Windows разрешает
  открытие приложения по пользовательской ссылке.
- **Ссылка истекла.** Challenge одноразовый; начните привязку заново и не
  используйте старую вкладку.
- **Связь не устанавливается после подтверждения.** Проверьте, что служба PC
  Remote работает, компьютер доступен Home Assistant по локальной сети, порт
  PC Remote разрешён локальным брандмауэром, а TLS-сертификат не менялся.
- **Wake-on-LAN не включает ПК.** Проверьте MAC и broadcast-адрес, включите WOL
  в BIOS/UEFI и драйвере сетевой карты; беспроводные адаптеры могут не
  поддерживать пробуждение после полного выключения.

Если проблема сохраняется, приложите только обезличенное сообщение из журнала
Home Assistant и версию интеграции. Не публикуйте содержимое `.storage` или
экспорт с секретами.
