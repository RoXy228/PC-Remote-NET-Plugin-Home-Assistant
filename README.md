# PC Remote для Home Assistant

Кастомная интеграция Home Assistant для управления Windows-компьютерами с
установленным PC Remote.NET. Репозиторий публичный и содержит только исходный
код интеграции в `custom_components/pc_remote` — без профилей, паролей,
токенов и ключей привязки.

Интеграция не открывает новые порты и не является отдельным сервером. Команды
передаются Windows-приложению по существующему защищённому протоколу PC Remote.
Для включения компьютера используется встроенная интеграция Home Assistant
`wake_on_lan`.

## Возможности

- безопасная привязка одного или нескольких Windows-ПК из браузера на самом ПК;
- управление из панели Home Assistant, действий и автоматизаций;
- Wake-on-LAN с параметрами, полученными при привязке;
- настраиваемые голосовые сценарии для `Yandex.Station Intents`;
- два способа настройки Алисы: обычная форма в панели и ручной YAML-редактор в
  этой же панели;
- отдельные подтверждения опасных голосовых действий, не конфликтующие с
  общими фразами «да», «нет» и «отмена»;
- экспорт без ключей и отдельный экспорт с ключами для локальной резервной
  копии.

## Что нужно заранее

- работающий Home Assistant;
- HACS или доступ к каталогу конфигурации Home Assistant;
- PC Remote.NET на каждом Windows-компьютере, которым нужно управлять;
- браузер на том же Windows-компьютере для первичной привязки;
- для голосового управления — установленный и настроенный
  [Yandex.Station Intents](https://github.com/dext0r/ha-yandex-station-intents).

Для автоматической привязки PC Remote.NET должен поддерживать ссылку
`pcremote://` и Home Assistant pairing bridge. После установки совместимой
сборки запустите PC Remote.NET хотя бы один раз, чтобы Windows зарегистрировала
обработчик ссылки.

## Установка через HACS

1. Откройте **HACS → Интеграции → ⋮ → Пользовательские репозитории**.
2. Добавьте:

   ```text
   https://github.com/RoXy228/PC-Remote-NET-Plugin-Home-Assistant
   ```

3. Выберите тип **Integration**.
4. Найдите **PC Remote**, скачайте его и перезапустите Home Assistant.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию** и
   выберите **PC Remote**.

Добавление интеграции создаёт в HA только её единственную запись. Привязка
компьютеров делается отдельно — в панели **PC Remote** в боковом меню.

## Ручная установка

Скопируйте каталог `custom_components/pc_remote` из репозитория в каталог
конфигурации Home Assistant:

```text
<config>/custom_components/pc_remote/
```

Например, итоговый путь: `/config/custom_components/pc_remote/manifest.json`.
Перезапустите Home Assistant и добавьте интеграцию через интерфейс.

## Привязка компьютера

Привязку нужно начинать в браузере, открытом именно на том Windows-ПК, который
должен появиться в Home Assistant.

1. Откройте Home Assistant на нужном ПК и войдите администратором.
2. В боковой панели откройте **PC Remote**.
3. Нажмите **Связать с этим ПК**.
4. Подтвердите открытие ссылки `pcremote://pair` в браузере. Если браузер не
   предложил открыть приложение, используйте появившуюся кнопку **Открыть PC
   Remote**.
5. Подтвердите разрешение в окне PC Remote.NET.
6. Дождитесь появления карточки компьютера в панели.

Ссылка одноразовая и быстро истекает. Для повторной привязки используйте
**Привязать заново** в карточке нужного ПК: название, внешний адрес и параметры
Wake-on-LAN сохраняются, а ключи связи заменяются.

При привязке автоматически переносятся локальный адрес, MAC-адрес,
TLS-отпечаток и параметры WOL. Ключи создаются отдельно для Home Assistant и
хранятся только в локальном хранилище HA.

> Для привязки предпочтителен HTTPS. При обычном HTTP ключи привязки проходят
> в пределах локальной сети без шифрования. Используйте такой вариант только в
> доверенной домашней сети.

## Управление из панели

В карточке ПК можно изменить имя, сетевые параметры, MAC, broadcast-адрес,
WOL-порт и включённость WOL, назначить основной компьютер, проверить связь или
выполнить действие.

Поддерживаемые команды PC Remote:

```text
STATUS
SHUTDOWN
REBOOT
SHUTDOWN:15   REBOOT:15
SHUTDOWN:30   REBOOT:30
SHUTDOWN:60   REBOOT:60
SHUTDOWN:90   REBOOT:90
SHUTDOWN:120  REBOOT:120
CANCEL
LOCK
SCREEN_OFF
```

Кнопка включения отправляет магический пакет через `wake_on_lan`; для этого ПК
должен поддерживать Wake-on-LAN, а MAC и broadcast-адрес должны быть верными.

## Алиса: настройка через панель

Голосовые команды создаются не в облаке PC Remote, а как обычные сценарии
вашего уже установленного `Yandex.Station Intents`. Всё настраивается в панели
**PC Remote → Алиса**.

### Аккаунты Яндекса

Панель показывает включённые записи `Yandex.Station Intents` без токенов и
паролей. Если такая запись одна, она выбирается автоматически. Если записей
несколько, отметьте в разделе **Аккаунты Яндекса** один или несколько аккаунтов,
которым разрешено выполнять голосовые сценарии PC Remote. Пока не выбран хотя
бы один аккаунт, предпросмотр и применение голосовой конфигурации недоступны.

При генерации каждый интент получает поле `accounts` с отмеченными аккаунтами.
Поэтому аккаунт, не выбранный в панели, не сможет запустить ни обычную команду,
ни подтверждение выключения или перезагрузки — даже если он также подключён к
Home Assistant.

Перед первой публикацией голосовых сценариев нужны две вещи:

1. `Yandex.Station Intents` должен быть установлен и настроен.
2. Home Assistant должен использовать packages. В панели нажмите
   **Подготовить голосовую конфигурацию** и подтвердите операцию.

Панель добавит в `configuration.yaml` ровно этот include, если его ещё нет:

```yaml
homeassistant:
  packages: !include_dir_named packages
```

Она не меняет существующий другой вариант `homeassistant.packages` и не
создаёт второй раздел `homeassistant`. Если packages уже подключены иначе,
настройте этот include вручную или приведите конфигурацию к показанному виду.
Перед первым изменением `configuration.yaml` создаётся локальная копия
`configuration.yaml.pc_remote_voice.bak`.

Сам интеграционный файл всегда один:

```text
<config>/packages/pc_remote_voice.yaml
```

PC Remote владеет только этим файлом. Пользовательские интенты в
`configuration.yaml` и других packages он не переписывает.

### Режим «Настройка в панели»

Для каждого привязанного ПК доступны:

- отдельное имя для Алисы — например, «основной компьютер» или «ноутбук»;
- включение/выключение каждого действия;
- до восьми фраз на действие;
- предпросмотр итогового YAML;
- сохранение и кнопка **Применить и синхронизировать**.

Можно включить: пробуждение (WOL), блокировку, выключение экрана, проверку
связи, отмену таймера, выключение и перезагрузку. Для выключения и
перезагрузки панель также создаёт варианты таймеров на 15, 30, 60, 90 и 120
минут.

После **Применить и синхронизировать** интеграция атомарно записывает только
свой package, вызывает `yandex_station_intents.reload`, а затем запускает его
обычную синхронизацию. Если фраза уже занята существующим интентом, операция
будет остановлена с понятной ошибкой — старые сценарии не затираются.

Фразы должны быть уникальными во всех сценариях, содержать только кириллицу,
латиницу, цифры и пробелы и укладываться в лимит сценариев Yandex.Station
Intents. В частности, если в старом YAML уже есть «Включи компьютер», её нужно
удалить или переименовать до включения той же фразы для PC Remote.

## Алиса: ручной YAML в веб-панели

Выберите режим **Ручной YAML** в панели **Алиса**. Это редактор YAML именно
для голосовых сценариев PC Remote; он подходит, когда нужны свои фразы или
точное расположение `extra_phrases`.

Редактор принимает только безопасный поднабор конфигурации:

- один верхний раздел `yandex_station_intents`;
- внутри него только `intents`;
- у интента только `action`, `extra_phrases` и `accounts`;
- действия только `pc_remote.voice_command`, `pc_remote.voice_confirm` и
  `pc_remote.voice_cancel`;
- только привязанные `pc_id` и обязательные шаблоны источника команды.

Это намеренное ограничение: через PC Remote нельзя случайно сохранить в
голосовой package токены, ключи или произвольные команды Home Assistant.

Аккаунты не нужно и не следует вести отдельно в ручном YAML. Поле `accounts`
в нём допускается для совместимости с предпросмотром, но при предпросмотре и
применении PC Remote заменяет его у каждого интента выбранным в панели списком
**Аккаунты Яндекса**. Так ручной YAML не сможет открыть сценарий для другого
подключённого аккаунта случайно.

Начать проще всего так: настройте один ПК в режиме панели, нажмите
**Предпросмотр YAML**, скопируйте результат в ручной режим и измените фразы.
Минимальный безопасный пример:

```yaml
yandex_station_intents:
  intents:
    заблокируй основной компьютер:
      action:
        action: pc_remote.voice_command
        data:
          pc_id: "<id профиля из предпросмотра>"
          command: LOCK
          source_entity_id: "{{ entity_id | default('') }}"
          source_account: "{{ account | default('') }}"
```

Для альтернативных фраз используйте `extra_phrases`:

```yaml
yandex_station_intents:
  intents:
    разбуди основной компьютер:
      extra_phrases:
        - включи мой компьютер
      action:
        action: pc_remote.voice_command
        data:
          pc_id: "<id профиля из предпросмотра>"
          command: WAKE
          source_entity_id: "{{ entity_id | default('') }}"
          source_account: "{{ account | default('') }}"
```

После правки используйте **Предпросмотр YAML**, затем **Сохранить** и
**Применить и синхронизировать**. Не редактируйте
`packages/pc_remote_voice.yaml` прямо в файловой системе: при следующем
применении из панели файл будет перезаписан. Для ручного редактирования
используйте веб-редактор панели.

## Подтверждение выключения и перезагрузки

Любое голосовое выключение или перезагрузка — немедленное и с таймером — не
выполняется сразу. PC Remote создаёт ожидание на 15 секунд и произносит точную
фразу подтверждения, например:

```text
подтверждаю действие с основной компьютер
```

Для отказа используется отдельная фраза:

```text
отменяю действие с основной компьютер
```

Эти фразы привязаны к конкретному ПК и к точному сочетанию колонки и аккаунта,
которое передаёт `Yandex.Station Intents`. Они специально не используют общие
«да», «нет» и «отмена»: такие слова часто уже ожидаются другими автоматизациями
Home Assistant и могли бы подтвердить не то действие.

Для выключения, перезагрузки, подтверждения и отмены обязательно используйте
режим `websocket` в Yandex.Station Intents. В нём интеграция передаёт колонку,
услышавшую команду, поэтому PC Remote может связать подтверждение с её точным
идентификатором и произнести ответ на ней. В режиме `device` идентификатор
колонки не передаётся: безопасные команды могут работать без адресного ответа,
но опасные действия и их подтверждение PC Remote намеренно отклоняет.

Для собственного ручного сценария подтверждения используйте те же данные
источника и не добавляйте `command`:

```yaml
yandex_station_intents:
  intents:
    подтверждаю действие с основной компьютер:
      action:
        action: pc_remote.voice_confirm
        data:
          pc_id: "<id профиля из предпросмотра>"
          source_entity_id: "{{ entity_id | default('') }}"
          source_account: "{{ account | default('') }}"
    отменяю действие с основной компьютер:
      action:
        action: pc_remote.voice_cancel
        data:
          pc_id: "<id профиля из предпросмотра>"
          source_entity_id: "{{ entity_id | default('') }}"
          source_account: "{{ account | default('') }}"
```

## Действия Home Assistant

Интеграция регистрирует обычные действия:

- `pc_remote.execute` — выполнить команду PC Remote;
- `pc_remote.wake` — отправить Wake-on-LAN;
- `pc_remote.cancel_timer` — отменить таймер ПК.

Для голосового слоя предусмотрены:

- `pc_remote.voice_command` — безопасная команда либо начало подтверждаемого
  выключения/перезагрузки;
- `pc_remote.voice_confirm` — подтверждение ожидающего действия;
- `pc_remote.voice_cancel` — отмена ожидающего подтверждения.

`pc_id` необязателен у обычных действий и тогда выбирается основной компьютер.
В голосовом YAML он указывается явно, чтобы фраза всегда управляла именно тем
ПК, который выбран в панели.

Обычные действия Home Assistant предназначены для собственных автоматизаций и
не добавляют голосовое подтверждение сами по себе. Защита с подтверждением
работает для сценариев, созданных в разделе **Алиса**.

## Экспорт и безопасность

Обычный экспорт профилей не содержит ключей. Экспорт с секретами предназначен
только для защищённой локальной резервной копии и требует отдельного
подтверждения. Никогда не добавляйте его в Git, не прикладывайте к issue и не
публикуйте в логах.

Обычный экспорт можно импортировать как настройки: у существующих профилей
ключи сохранятся, а новые потребуется привязать заново. Для переноса готовых к
управлению профилей нужен полный экспорт с ключами.

## Обновление

Через HACS: **HACS → Интеграции → PC Remote → Обновить**, затем перезапустите
Home Assistant.

Для локального клона:

```powershell
cd <путь-к-репозиторию>
git pull --ff-only origin main
git status
```

После ручного обновления содержимого `custom_components/pc_remote` перезапустите
Home Assistant.

## Устранение неполадок

- **Видны две записи PC Remote.** Это записи интеграции, а не два ПК. Удалите
  лишнюю через меню **⋮** в «Устройства и службы», оставьте одну.
- **Нет панели PC Remote.** Убедитесь, что интеграция установлена, HA
  перезапущен, а текущий пользователь — администратор. Обновите страницу с
  очисткой кэша.
- **`pcremote://` не открывается.** Установите совместимый PC Remote.NET,
  запустите его один раз и повторите привязку.
- **Кнопка привязки недоступна.** Откройте Home Assistant в браузере именно на
  Windows-ПК с PC Remote.NET.
- **«Подготовить голосовую конфигурацию» отказывается менять YAML.** В
  `configuration.yaml` уже есть другой способ подключения `packages`; панель
  намеренно его не перезаписывает. Проверьте include вручную.
- **Алиса не выполняет фразу после применения.** Убедитесь, что
  Yandex.Station Intents настроен, нет коллизии фразы со старым интентом и
  синхронизация завершилась без ошибки в журнале HA.
- **WOL не включает ПК.** Проверьте MAC, broadcast-адрес, настройки BIOS/UEFI
  и драйвера сетевой карты.

При сообщении о проблеме приложите обезличенную ошибку журнала и версию
интеграции. Не публикуйте `.storage`, экспорт с ключами или содержимое
приватных профилей.
